# Frontend — план вех (Фаза 3)

Фундамент сделан в [F1](F1-foundation.md). Дальше — **M22** (API под макеты), затем F2–F7. Задания вех — файлы `F2…F7` в этой папке, по образцу backend-вех. Здесь — объём, токены и обязательные приёмы скорости.

**Порядок документов для каждой F-вехи:** файл вехи → [`SCREENS.md`](SCREENS.md) (что делает каждая кнопка, какой эндпоинт) → [`mockups/`](mockups/README.md) (как выглядит, 26 макетов HTML + PNG).

**Дизайн:** [`mockups/`](mockups/README.md) — 26 макетов: 19 экранов для десктопа, 5 для телефона, 2 письма. Каждый экран делается по макету точно; сверка — снимками `npm run screens` (с F2).

## Обязательные приёмы скорости и плавности
1. **TanStack Query** для всех запросов: `staleTime` (поиск 60 с, карточка 5 мин, справочники 1 ч), отмена устаревших запросов, retry 2, дедупликация.
2. **Prefetch** карточки при наведении/фокусе на результат поиска (`queryClient.prefetchQuery`).
3. **Debounce 300 мс** для поиска и подсказок; минимум 2 символа.
4. **Skeleton** вместо спиннеров для списков и карточки; размеры совпадают с реальным контентом (без сдвигов вёрстки).
5. **Оптимистичные обновления** для маячков (создать, пауза, удалить) с откатом и toast при ошибке.
6. **Code splitting:** каждая страница — `React.lazy`; админка и Recharts — отдельные чанки; проверить `vite build --report`/`rollup-plugin-visualizer`.
7. **Картинки:** `loading="lazy"`, `decoding="async"`, фиксированные `width/height`, цветная заглушка до загрузки.
8. **Виртуализация** длинных списков (журнал, пользователи в админке).
9. **Error Boundary** на уровне страниц + понятные сообщения для кодов ошибок API.
10. **Опрос в админке** через `refetchInterval: 30000`, только когда вкладка видима.
11. **Бюджет:** LCP < 2.5 с, главная < 200 КБ JS gzip, CLS < 0.1.
