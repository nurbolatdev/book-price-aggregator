# Экраны frontend: макеты, маршруты, кнопки → API

Главный документ для frontend-вех F1–F7. Каждый экран делается **по макету**: размеры, отступы, цвета, тексты и порядок блоков берутся из файлов в [`mockups/`](mockups/README.md). Если что-то в макете не описано здесь — смотреть макет; если макет и этот документ расходятся — прав этот документ, а расхождение записать в отчёт вехи.

- Эталон вёрстки: `mockups/NN-*.html` — статичная HTML-вёрстка с inline-стилями, открывается в браузере. Числа (px, цвета, радиусы) переносить в Tailwind **точно**.
- Эталон картинки: `mockups/png/NN-*.png` — как экран должен выглядеть. Перед сдачей вехи сравнить свой экран со скриншотом при той же ширине (1280 px для десктопа, 390 px для телефона).
- Данные в макетах — примеры. Реальные данные — из API (`docs/03-api-contract.md`, `docs/api/openapi.json`).
- Элементы, помеченные **[M22]**, требуют эндпоинтов из backend-вехи M22 — выполнена (backend-веха M22, после F1 и до F2): эндпоинты описаны в `docs/03-api-contract.md` и `docs/api/openapi.json`.

## 1. Общие правила

### Токены и форматы
Токены дизайна — в `ROADMAP.md` (цвета, шрифты Unbounded/Onest, радиусы 10/16/20 px). Дополнительно из макетов:

| Что | Правило |
|---|---|
| Контейнер страницы | `max-width: 1200px`, поля 24 px; админка — меню 240 px + контент с полями 28 px |
| Цена | `Intl.NumberFormat('ru-RU')` + ` ₸`, жирным: `3 150 ₸`; «от 3 150 ₸» в карточках-подборках |
| Старая цена | зачёркнуто, цвет `#5A6576` |
| Время обновления | относительное: «2 ч назад», «вчера», дата `20.10.2026` старше 7 дней (`Intl.RelativeTimeFormat('ru')`) |
| Магазин | название из `GET /stores` (`name`), не код; выключенные магазины не показывать в фильтрах |
| Обложка | `coverUrl`; нет обложки — цветная плашка с названием (как в макетах), цвет — по `editionId % 6` из набора `#FCE3D3 #DCE8FB #E2F1E6 #EDE5F7 #F7EDD0 #E3E7F0` |
| Оценка цены | `priceVerdict.label`: `BELOW_AVERAGE` → зелёная плашка «Ниже средней за 3 месяца на N%»; `ABOVE_AVERAGE` → серая «Выше средней на N%»; `AVERAGE` → «Обычная цена»; `NOT_ENOUGH_DATA` → не показывать |
| Статусы в админке | цвет + текст всегда вместе (OK — зелёный, частичные ошибки — оранжевый, не отвечает — красный, выключен — серый) |
| Иконки | inline SVG (lucide), `aria-hidden="true"`; кнопка только с иконкой — `aria-label` |
| Цели касания | ≥ 44 px; на телефоне кнопки нижней панели ≥ 48 px |

### Шапка (все пользовательские страницы)
В макете 05 в шапке пропущен пункт «Скидки недели» — делать по таблице ниже. Страницы входа, регистрации, пароля, подтверждения и отписки — шапка только с логотипом. Телефон — макеты 16, 25, 26: логотип + иконки (поиск, маячки) или «Войти», меню «≡».

| Элемент | Гость | Вошёл |
|---|---|---|
| Логотип → `/` | ✓ | ✓ |
| Вариант А — навигация (главная, `/deals`, `/beacons`, `/profile`, 404): «Каталог» → `/catalog`, «Скидки недели» → `/deals`, «Мои маячки» → `/beacons` (макеты 01, 14) | «Мои маячки» ведёт на вход с `next=/beacons` | ✓ |
| Вариант Б — поиск (`/search`, `/catalog`, `/editions/:id`): поле поиска на всю свободную ширину + «Мои маячки» (макеты 02, 03); «Каталог» и «Скидки недели» в этом варианте не показываются | ✓ | ✓ |
| Активный пункт — цвет `#C2410C`, `aria-current="page"` (макет 05) | ✓ | ✓ |
| Справа | кнопка «Войти» → `/login` | круг с первой буквой имени → меню (макет 15, «Шапка: меню пользователя»): email, Мои маячки, Профиль и настройки, Админ-панель (только `role=ADMIN`), Выйти |

«Выйти» → `POST /auth/logout {refreshToken}` → очистить токены и кэш TanStack Query → `/`.

### Ошибки API → что видит пользователь
| Код | Поведение |
|---|---|
| `TOKEN_EXPIRED` (401) на защищённом запросе | перехватчик axios: один `POST /auth/refresh`, повтор запроса; параллельные запросы ждут один и тот же refresh |
| refresh вернул 401 | выйти, toast «Сессия закончилась, войдите снова», `/login?next=` |
| `VALIDATION_FAILED` (422) | `fieldErrors` — под полями формы (макет 15, «ошибка поля») |
| `RATE_LIMITED` (429) | жёлтая плашка «Слишком много запросов. Подождите N секунд» (`Retry-After`); кнопка отправки неактивна с обратным отсчётом (макет 10) |
| `CONFLICT` (409) у маячка | toast «На эту книгу маячок уже стоит» со ссылкой «Изменить» → `/beacons` |
| `NOT_FOUND` (404) | экран 404 (макет 15) |
| 5xx / сеть | красная плашка «Не удалось загрузить… Повторить» на месте блока; при `navigator.onLine === false` — тёмная плашка «Нет подключения» (макет 15) |
| ошибка рендера | Error Boundary страницы (макет 15, «Что-то пошло не так») |

### 02 · Результаты поиска `/search`, `/catalog`
Макеты: `02-search` (десктоп), `16-search-mobile`, `17-filters-mobile` (телефон < 768 px).

| Элемент | Действие / данные |
|---|---|
| Все фильтры и сортировка | в URL (`useSearchParams`), ссылку можно отправить другу; изменение фильтра → `page=0` |
| Запрос | `GET /search?q&stores&minPrice&maxPrice&inStock&binding&language&sort&page&size=20`; на `/catalog` без `q` **[M22]** |
| Заголовок | `«{q}»` + «Найдено {totalElements} изданий»; на `/catalog` — «Каталог» |
| Фильтр «Магазины» | чекбоксы по включённым магазинам; число справа — `GET /search/facets` **[M22]** |
| «Цена, ₸ от / до» | применяется по blur или Enter, не на каждую цифру |
| «Только в наличии» | `inStock`, по умолчанию включён |
| «Переплёт», «Язык» | несколько значений: `binding=HARDCOVER,PAPERBACK`, `language=ru,kk` **[M22]**; числа — из facets |
| «Сортировка» | `PRICE_ASC` «Сначала дешевле», `DISCOUNT_DESC` «Максимальная скидка», `RELEVANCE` «По релевантности» (по умолчанию при `q`), `STORES_DESC` «Больше магазинов» (по умолчанию в каталоге) |
| Карточка издания | обложка, название → `/editions/{editionId}`, «автор · издательство, год, переплёт», чипы цен `offers` (лучшая — зелёный фон `#E7F5EE`), справа «Лучшая цена», `bestPrice.price`, «{магазин} · в наличии/нет в наличии» |
| «Сравнить» | `/editions/{editionId}`; prefetch при наведении/фокусе |
| Кнопка-колокольчик | гость → `/login?next=/editions/{id}?beacon=1`; вошёл → открыть окно маячка (04) поверх списка |
| «Показать ещё N изданий» | следующая страница, дописывается в список (`useInfiniteQuery`), N = `totalElements − показано` |
| Телефон: «Фильтры · N» | открывает нижнюю панель (17); «Показать N изданий» применяет и закрывает; «Сбросить» очищает |

Состояния: 3 скелетона карточки; 0 результатов → блок «ничего не нашли» (макет 15) с «Сбросить фильтры» и «Часто ищут»; ошибка — плашка.

### 04 · Окно маячка (модалка)
Макет: `04-beacon-modal`; ошибки — макет 15.

| Элемент | Действие / данные |
|---|---|
| Окно | `role="dialog"`, фокус внутри, Esc и «Закрыть» закрывают, фокус возвращается на кнопку, открывшую окно; на телефоне — нижняя панель на всю ширину |
| Книга | обложка, название, `label` издания, «Сейчас от {bestPrice}» |
| «Когда сообщить» | радио: `ANY_DROP`; `BELOW_PRICE` + поле цены (по умолчанию — лучшая цена минус 10%, округлить до 10 ₸); `DISCOUNT_PERCENT` + поле 1–90 % (по умолчанию 15) |

| «Поставить маячок» | `POST /beacons` (создание) или `PATCH /beacons/{id}` (изменение); валидация React Hook Form + Zod до отправки; оптимистично добавить в кэш `beacons`; успех → toast «Маячок поставлен» + «Открыть»; 409 → toast со ссылкой; 422 → ошибки под полями |
| «Отмена» | закрыть без запроса |

### 05 · Мои маячки `/beacons`
Макеты: `05-beacons`, телефон — `26-beacons-mobile`; пусто — макет 15.

| Элемент | Действие / данные |
|---|---|
| Список | `GET /beacons` (все сразу); вкладки фильтруют на клиенте: Все · Сработали (`TRIGGERED`) · Ждут (`ACTIVE`) · На паузе (`PAUSED`), числа в вкладках — по списку |
| Сработавший маячок | выделенная карточка (фон `#FFF4EC`, рамка `#C2410C`), плашка «Сработал {сегодня/вчера/дата} в {время}» (`lastTriggeredAt`), «Цель: … · сейчас {цена} на {магазин}» |
| «Купить за {цена}» | `currentBestUrl` **[M22]** в новой вкладке |
| «Следить дальше» | `PATCH /beacons/{id} {status: ACTIVE}` — карточка уходит в «Ждут» |
| Строка маячка | обложка, название → `/editions/{editionId}`, автор, «Цель: любое снижение / ниже X ₸ / скидка от N%» |
| «Сейчас лучшая» | `currentBestPrice`; подпись: `ANY_DROP` — «было {baselinePrice} при установке»; `BELOW_PRICE` — «ещё {current − target} до цели»; `DISCOUNT_PERCENT` — «сейчас скидка N%» (от `baselinePrice`); пауза — «пауза с {statusChangedAt}» **[M22]** |
| Плашка статуса | Ждёт / Сработал / На паузе |
| «Изменить условие» | окно маячка в режиме изменения |
| «Поставить на паузу» / «Возобновить» | `PATCH {status: PAUSED|ACTIVE}`, оптимистично, откат + toast при ошибке |
| «Удалить маячок» | оптимистично убрать + toast «Маячок удалён · Отменить» (5 с); запрос `DELETE` уходит, когда toast закрылся без «Отменить» |
| Панель «Уведомления» | email + плашка подтверждён/не подтверждён (`/me`); «Как часто» → `PATCH /me {notifyFrequency: INSTANT|DAILY}`; «Еженедельная подборка скидок» → `PATCH /me {weeklyDigest}` — сохраняется сразу, toast «Сохранено» |
| «Как работает маячок» | статичный текст + ссылка `/profile` |

### 06 · Письмо «Цена упала»
Макет: `06-email-price-drop`. Это шаблон backend (Thymeleaf, M19), не страница frontend. Ссылки письма ведут на `/editions/{id}`, `/unsubscribe?token=` и `/profile`.

### 24 · Письмо «Подборка недели»
Макет: `24-email-weekly-digest`. Шаблон backend (Thymeleaf, M22 задача 8), не страница frontend. В письме все издания подборки (до 8), строка «…и ещё N книг» в макете — только чтобы не растягивать картинку. Ссылки: карточка → `/editions/{id}`, «Все скидки недели» → `/deals`, «Отключить подборку» и «Настройки уведомлений» → `/profile`.

### 08 · Регистрация `/register` и «Подтвердите почту» `/check-email`
Макет: `08-signup` (слева — форма, справа — экран после отправки).

| Элемент | Действие / данные |
|---|---|
| Имя, Email, Пароль | Zod: имя 1–100, email, пароль ≥ 8 (подсказка «Минимум 8 символов»); `autocomplete` name/email/new-password |
| Согласие на письма | обязательный чекбокс; без него кнопка неактивна (на backend не отправляется) |
| «Создать аккаунт» | `POST /auth/register` → 201 → `/check-email?email=…`; `EMAIL_TAKEN` → ошибка под email со ссылкой «Войти»; 429 → плашка |
| «Уже есть аккаунт? Войти» | `/login` |
| `/check-email` | текст с email из параметра; «Отправить письмо ещё раз» → `POST /auth/resend-verification {email}` (кнопка неактивна 60 с после нажатия, toast «Письмо отправлено»); «Зарегистрируйтесь заново» → `/register` |

После регистрации пользователь **не входит автоматически** (backend не выдаёт токены при регистрации) — на `/check-email` есть ссылка «Войти».

| Элемент | Действие / данные |
|---|---|
| «Войти» | `POST /auth/login` → сохранить `accessToken` в памяти (Zustand); refresh-токен — в cookie `HttpOnly` (с M22/F4, ADR-005; до F4 — `localStorage`, ключ `kr.refreshToken`); `user` — в кэш `/me`; переход на `next` или `/` |
| `INVALID_CREDENTIALS` | красная плашка над формой, поле email с красной рамкой |
| `RATE_LIMITED` | жёлтая плашка + кнопка неактивна с отсчётом `Retry-After` |
| «Забыли пароль?» | `/forgot-password` |
| «Создать аккаунт» | `/register` |

### 11 · Восстановление пароля
Макет: `11-password-reset` (4 состояния).

| Шаг | Действие |
|---|---|
| `/forgot-password` | `POST /auth/forgot-password {email}` → всегда экран «Проверьте почту» (шаг 2) |
| `/reset-password?token=` | два поля пароля, проверка совпадения на клиенте; `POST /auth/reset-password {token, newPassword}` → toast «Пароль изменён, войдите» → `/login` (backend завершил все сессии) |
| `TOKEN_INVALID` / `TOKEN_EXPIRED` | шаг 4 «Ссылка устарела» → «Запросить новую ссылку» → `/forgot-password` |

### 12 · Подтверждение email `/verify-email?token=`
Макет: `12-verify-email`. При загрузке — `POST /auth/verify-email {token}` (ссылка из письма ничего не меняет на чужой стороне, кроме подтверждения — запрос при загрузке допустим). Успех → левая панель, обновить `/me` в кэше. Ошибка токена → правая панель с формой повторной отправки.

### 13 · Отключение маячка `/unsubscribe?token=`
Макет: `13-unsubscribe`. **При загрузке запрос не отправлять** (почтовые сканеры открывают ссылки сами). Кнопка «Поставить маячок на паузу» → `POST /beacons/unsubscribe {token}` → правая панель с названием книги из ответа. Ошибка токена → текст «Ссылка больше не действует…». Название книги до нажатия неизвестно — показать «Маячок из письма» без обложки (в макете обложка — пример после нажатия).

### 14 · Профиль и настройки `/profile`
Макет: `14-profile`.

| Блок | Действие / данные |
|---|---|
| Плашка «Почта не подтверждена» | только при `emailVerified=false`; «Отправить письмо ещё раз» → `POST /auth/resend-verification` |
| «Личные данные» | имя → `PATCH /me {name}`; email только для чтения + плашка подтверждён/не подтверждён |
| «Уведомления» | как панель на экране 05; сохраняется сразу |
| «Пароль» | `POST /me/password {currentPassword, newPassword, refreshToken}` **[M22]** → toast «Пароль изменён, другие устройства отключены»; неверный текущий → ошибка под полем |
| «Выйти» | `POST /auth/logout` |
| «Выйти на всех устройствах» | `POST /auth/logout-all` **[M22]** → `/login` |
| «Удалить аккаунт…» | окно подтверждения с полем пароля → `DELETE /me {password}` **[M22]** → очистить всё → `/` + toast «Аккаунт удалён» |

### 15 · Состояния и компоненты
Макет: `15-states`. Не страница, а набор: 404, пустой поиск, ошибки загрузки и нет сети, Error Boundary, toasts (снизу справа, 4 с, на телефоне снизу по центру; `role="status"`, ошибки — `role="alert"`), скелетоны, меню пользователя, пустой список маячков, ошибка поля и гость в окне маячка. Все эти компоненты делаются в F1 (каркас) и используются во всех вехах.

### 09, 18–23 · Админ-панель `/admin/*`
Макеты: `09-admin-overview`, `18-admin-parsers`, `19-admin-queues`, `20-admin-users`, `21-admin-notifications`, `22-admin-matching`, `23-admin-events`. Отдельный lazy-чанк; данные обновляются `refetchInterval: 30000` только при видимой вкладке; подпись «последнее обновление HH:MM».

| Раздел | Путь | Данные и действия |
|---|---|---|
| Обзор (09) | `/admin` | период 24 ч / 7 дней / 30 дней → `GET /admin/stats?period=`; KPI-карточки; «Состояние сервисов» — `GET /admin/health` (`components`: db → PostgreSQL, redis → Redis, rabbit → RabbitMQ, mail → SMTP, scheduler → Планировщик; `metrics.httpP95Millis` под «Backend API»); таблица парсеров — `GET /admin/parsers`; «Активность за 14 дней» — `GET /admin/activity?days=14` (Recharts, столбцы поиски и новые маячки); «Очереди» — `GET /admin/queues`; «Последние события» — `GET /admin/events?size=5`; «Топ запросов» — `GET /admin/search/top?period=24h`; «смотреть список» → `/admin/events#zero` |
| Парсеры (18) | `/admin/parsers` | таблица `GET /admin/parsers`; переключатель «Вкл.» → окно подтверждения при выключении → `PATCH /admin/stores/{code} {enabled}`; «Запустить» → `POST /admin/parsers/{code}/run` → toast «Задача в очереди»; 409/503 — сообщение в строке; «Запустить все включённые» — по очереди для `enabled && hasParser`, итог одним toast; выключенный магазин — кнопка неактивна с подсказкой |
| Очереди (19) | `/admin/queues` | таблица `GET /admin/queues` (`ready`, `unacknowledged`, `consumers`, `ackRate`); блок dead letter: число из очереди `kr.dead-letter`, «Вернуть в работу» → `POST /admin/queues/dead-letter/requeue` → плашка «Возвращено {requeued}, пропущено {skipped}» |
| Пользователи (20) | `/admin/users` | `GET /admin/users?q=&verified=&page=` **[M22: q, verified]**; поиск с debounce 300 мс; чипы фильтра; таблица; пагинация «Назад/Вперёд» |
| Маячки и письма (21) | `/admin/notifications` | KPI из `GET /admin/stats`; журнал писем `GET /admin/notifications?status=&page=` **[M22]**; чипы статуса; «Повторить» у FAILED → `POST /admin/notifications/{id}/retry` **[M22]** |
| Каталог и сопоставление (22) | `/admin/matching` | список `GET /admin/offers/pending-review?page=`; выбор предложения → правая панель; «Найти издание» → `GET /search?q=` (до 5 изданий как варианты); «Привязать к изданию» → `POST /admin/offers/{id}/match {editionId}`; «Отклонить» → `POST /admin/offers/{id}/reject`; после действия — следующее предложение |
| Журнал событий (23) | `/admin/events` | `GET /admin/events?level=&page=`, чипы уровня, строки раскрываются (`details`), длинный список — TanStack Virtual + подгрузка; справа «Запросы без результатов» — `GET /admin/search/zero-results?period=24h|7d` |

Подписи к счётчикам из макетов, которых нет в API (например «уникальные посетители»), заменить на то, что реально отдаёт API (`activeUsers` — «активны за период»).

## 3. Что было исправлено в макетах при сверке с API
- Убраны рубрики («Художественная литература») — категорий в модели данных нет; крошки строятся от поиска.
- «Мало в наличии» → «В наличии / Нет в наличии» (в API только `inStock`).
- Убран блок «Добавить список книг» — это функция v2.
- «Изменить email» на экране подтверждения → «Зарегистрируйтесь заново» (смены email в API нет).
- Магазины в примерах — те, что работают; выключенные показываются серым.
- Добавлены экраны: вход, восстановление пароля, результат подтверждения email, отписка, профиль, состояния, поиск и фильтры на телефоне, шесть разделов админки.
- Добавлены макеты 24 (письмо «Подборка недели»), 25 (главная на телефоне), 26 (маячки на телефоне); правила для остальных экранов на телефоне и планшете — в [`mockups/README.md`](mockups/README.md#адаптивность).
- Для кнопок, которым не хватало API, заведена backend-веха [M22](../backend/M22-api-for-ui.md).
