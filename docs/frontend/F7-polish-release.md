# F7 — Полировка, доступность, скорость, релиз

**Ветка:** `feature/f7-polish` · **Зависит от:** F6 · **Оценка:** 2 дня

## Цель
Довести frontend до уровня портфолио: все состояния на месте, доступность с клавиатуры и для скринридеров, Lighthouse ≥ 90, сквозные тесты главных сценариев, финальная сверка всех экранов с макетами, README и тег релиза.

## Перед началом прочитать
`docs/frontend/ROADMAP.md` (приёмы скорости и бюджет), `docs/frontend/mockups/README.md` (адаптивность, как сверять), макет `15-states`, `docs/performance.md`.

## Задачи

### 1. Состояния
- [ ] Пройти все страницы и проверить по макету 15: загрузка (скелетоны тех же размеров), пусто, ошибка блока с «Повторить», нет сети (`OfflineBanner`, запросы ставятся на паузу и повторяются при возвращении сети), Error Boundary страницы, 404.
- [ ] Медленная сеть (DevTools «Slow 3G»): нет «прыжков» вёрстки, кнопки показывают загрузку.

### 2. Доступность
- [ ] Все интерактивные элементы доступны с клавиатуры, порядок Tab логичный, фокус виден; «Перейти к содержимому» первой ссылкой.
- [ ] `aria-label` у кнопок-иконок, `aria-live` для toasts и результатов поиска («Найдено N изданий»), связь ошибок с полями, `lang="ru"`.
- [ ] Контраст текста ≥ 4.5:1 (проверка axe), цели касания ≥ 44 px, `prefers-reduced-motion`.
- [ ] `@axe-core/playwright` в сквозных тестах: 0 нарушений уровня serious/critical на главной, поиске, карточке, маячках, входе.

### 3. Скорость
- [ ] Проверить приёмы из ROADMAP §1–11 (prefetch, debounce, staleTime, code splitting, lazy-картинки, виртуализация, опрос только на видимой вкладке).
- [ ] Бюджет: LCP < 2.5 с, CLS < 0.1, начальный JS главной ≤ 200 КБ gzip; Lighthouse (mobile) ≥ 90 по Performance, Accessibility, Best Practices, SEO для `/`, `/search`, `/editions/:id`.
- [ ] Шрифты: `font-display: swap`, предзагрузка Onest 400/700 и Unbounded 700 (latin + cyrillic); nginx: gzip/brotli, долгий кэш для `assets/*` с хэшем, без кэша для `index.html`.
- [ ] SEO: `title`/`description` на страницах, `robots.txt`, `og:`-теги главной и карточки.

### 4. Сквозные тесты — Playwright (`e2e/`)
- [ ] На моках MSW: поиск → фильтр → карточка → «Следить за ценой» → вход → маячок создан → «Мои маячки» → пауза → удаление с «Отменить».
- [ ] Регистрация → `/check-email`; восстановление пароля; админ: выключить магазин с подтверждением.
- [ ] Отдельный набор `e2e:live` против `docker compose up` (демо-профиль backend) — главная, поиск, карточка, вход админа; запускается вручную.
- [ ] CI `frontend.yml`: добавить `npx playwright test` (моки) и загрузку отчёта при падении.

### 5. Финальная сверка с макетами
- [ ] `npm run screens` для всех маршрутов при 1280 и 390 px; сравнить с каждым PNG из `mockups/png/` (01–26, кроме писем 06 и 24). Таблица сверки в отчёте вехи: экран → совпадает / расхождение и причина.

### 6. Документация и релиз
- [ ] Корневой `README.md`: раздел «Frontend» — стек, как запустить (`npm run dev`, `dev:mock`, `docker compose up`), скриншоты 3–4 экранов (из `npm run screens`, сжатые) вместо макетов.
- [ ] `docs/README.md` — статусы F1–F7; `docs/frontend/ROADMAP.md` — «Фаза 3 завершена».
- [ ] Тег `v3.0.0` после мерджа — только по подтверждению автора.
