# Макеты UI KitapRadar

Эталон внешнего вида frontend (вехи F1–F7). Каждый макет есть в двух видах:
- `NN-*.html` — статичная вёрстка с inline-стилями. Открыть в браузере, посмотреть размеры и цвета в DevTools. Все размеры, отступы, цвета и радиусы переносить в Tailwind **точно**.
- `png/NN-*.png` — снимок того, как экран должен выглядеть, при ширине из таблицы.

Что делает каждая кнопка и откуда берутся данные — в [`../SCREENS.md`](../SCREENS.md). Если макет и `SCREENS.md` расходятся, прав `SCREENS.md`.

Данные в макетах — примеры. Шрифты Unbounded и Onest подключаются из Google Fonts; без сети браузер покажет запасной шрифт — это нормально для просмотра, но снимки сравнивать только со шрифтами.

## Адаптивность

Точки перелома: телефон `< 768 px`, планшет `768–1199 px`, десктоп `≥ 1200 px` (контейнер 1200 px).

| Экран | Телефон | Планшет |
|---|---|---|
| Главная, поиск, карточка, маячки | по своим мобильным макетам (25, 16–17, 07, 26) | десктопная вёрстка, сетки в 2 колонки, правая колонка карточки и маячков — под основной |
| Окно маячка | нижняя панель на всю ширину, высота по содержимому, полоска-ручка сверху | как десктоп (560 px по центру) |
| Вход, регистрация, пароль, подтверждение, отписка | одна колонка, карточка формы на всю ширину, поля страницы 16 px (правые половины макетов 08 и 10 — это другие состояния того же экрана, а не вторая колонка) | как десктоп |
| Профиль | блоки друг под другом, кнопки на всю ширину | как десктоп в одну колонку |
| Админка | не адаптируется: при ширине `< 1024 px` — плашка «Админ-панель рассчитана на экран от 1024 px» и горизонтальная прокрутка | как десктоп |

Мелочи на телефоне: на карточках «подешевели» строка «магазин · ещё в N магазинах» скрыта (макет 25); вкладки и чипы прокручиваются по горизонтали без переноса; все кнопки ≥ 44 px, кнопки нижней панели ≥ 48 px.

## Как сверять свою вёрстку

С F1 во frontend есть команда `npm run screens` (Playwright): снимает экраны приложения на моковых данных при ширине 1280 и 390 px в `frontend/screens/` (не коммитится). Перед сдачей вехи открыть рядом снимок и `png/` нужного макета и проверить: порядок блоков, тексты, размеры шрифтов, отступы, цвета, состояния. Найденные расхождения — исправить или записать в отчёт вехи с причиной.
