# ADR-001: RabbitMQ как брокер сообщений (Kafka — позже)

**Статус:** принято · **Дата:** 2026-10-20

## Контекст
Нужна фоновая обработка: задачи парсинга по магазинам, события изменения цены, отправка писем. Автор хочет попрактиковаться с брокером сообщений. Рассматривались RabbitMQ и Kafka.

## Решение
Используем **RabbitMQ 3.13** + Spring AMQP. Kafka — опциональная Фаза 4 для потока событий `price.changed` (аналитика).

## Почему
- Наши сценарии — **очереди задач** (одну задачу выполняет один исполнитель, нужны повторы и dead-letter). Это то, для чего создан RabbitMQ.
- Простота: один контейнер, веб-интерфейс, DLX и TTL из коробки, низкий порог входа.
- Объём событий маленький: хранение и «переигрывание» лога (сильная сторона Kafka) не нужны.

## Последствия
- (+) Быстрый старт, наглядная отладка в UI, легко объяснить на собеседовании.
- (+) Изоляция магазинов: отдельная очередь на магазин со своей параллельностью.
- (−) Нет долговременного лога событий — для аналитики цен используем таблицу `price_history`.
- (−) Нужна идемпотентность потребителей (сделано через Redis `processed:{messageId}`).
