# ADR-002: Парсеры — Java-модуль внутри backend

**Статус:** принято · **Дата:** 2026-10-20

## Контекст
Каркас из папки `BookPlatform` предлагал отдельные Python-сервисы парсеров. Альтернатива — парсеры на Java внутри Spring Boot.

## Решение
Парсеры пишем на **Java** (Jsoup, Playwright for Java) в пакете `parser/` того же приложения. Изоляция от API обеспечивается очередями RabbitMQ (отдельная очередь и параллельность на магазин) и Resilience4j.

## Почему
- Один язык и один стек — сильнее для Java-портфолио, меньше инфраструктуры.
- Общая модель данных и транзакции с `OfferIngestionService` без межсервисного контракта.
- Граница уже проведена через очереди: при необходимости модуль `parser` выносится в отдельный сервис-потребитель без переписывания логики.

## Последствия
- (+) Проще разработка, тесты и деплой.
- (−) Playwright увеличивает Docker-образ backend; браузер включается флагом `app.parser.browser.enabled`.
- (−) Тяжёлый парсинг делит ресурсы с API — смягчается ограничением параллельности потребителей.
